check what geometry can cheaply prove, render the rest for a human in one glance, and keep
the model advisory.

# Part I — Understand

## 1. Goal

**Problem.** Coding agents write code well and reason about 3D space badly. This is
structural, not a prompting deficiency ([landscape](../reference/landscape.md) §1). An agent
asked to design a part cannot be trusted to look at a render and judge whether it is right.

**Insight.** Do not ask the model to *see*. Make the geometry assert what it cheaply can,
render the rest fast for a human, and keep the model advisory.

**Outcome.** A standalone, domain-agnostic harness that makes CAx generation test-first.
`so101-biolab-automation` and `i3mega-pipettebot` are its first two consumers — both
independently built half this machinery and both explicitly defer the loop itself
(`so101-biolab-automation/docs/roadmap.md:47-58`, `:158-169`).

**Scope** (decided 2026-10-06): verification of **exported** CAx artifacts — CAD (the core,
v0), additive CAM, and BIM via IFC (data-gated, §13); CAE only as information for a human.
Robotics and lab automation stay in the consumer repos. **The inclusion test:** a check may
*gate* only if it measures the artifact directly; anything that rests on a chain of
judgements — a CAE result, an interpreted building code — may only *inform*. Broad scope,
narrow build order: nothing outside v0 starts without its trigger.

**Success for v0** is one sentence: *a human looks at an automatic multi-view render beside
a per-check verdict for a real estate part, and decides.* Not "the tool says correct" —
that verdict does not exist here by construction.

## 3. The approach

The honest primitive is not a machine oracle. It is **making the part cheap and fast to
judge, and honest about what it does not know.** Three layers, in this order of trust:

1. **Cheap deterministic preflight (necessary, not sufficient).** build-succeeds +
   manifold/watertight + bbox + mass, plus a browser-load check. Trustworthy for real
   *global/static* failures — including silent boolean-fusion feature loss, which is
   otherwise invisible. A gate against the obviously-broken, never a certificate of
   correctness.
2. **Auto-generated multi-view render as the PRIMARY gate.** For the defect classes the
   deterministic layer is blind to (a gusset over a hole, a hole that isn't through, a
   datum-offset mating feature), the real gate is a human looking at a fast, automatic
   3-view render. The harness's job is to make that glance instant, not to replace it.
3. **VLM as an assist, not an authority.** It annotates the render to draw the human's eye.
   It never gates, never auto-loops to "green", and cannot suppress human review. The system
   is fully functional with no model configured — which is why it is deferred out of v0
   entirely (§5).

**Why this ordering, and not the reverse.** The deterministic layer catches only
global/static/foreseen properties — roughly a third of real defects — and is blind to the
dominant class. Subordinating the render (the one signal that surfaces those) to a blind
gate is inverted. Worse, a blind-but-authoritative gate with revert-on-break **selects for
gaming**: a numerically-safe hack that dodges a check survives, while an honest fix that
risks a deterministic regression gets discarded. Hence: no auto-critique loop, no
auto-revert, human-driven iteration.

**`DesignSpec` survives only in a regression framing** — small and cheap (envelope, mass, a
few genuinely-mated clearances as two-sided fit *windows*), authored once and **reused
across many regenerations**: re-run after a build123d/OCCT bump, or a component reused
across assemblies. That is the only mode where pre-declaration earns its cost, so it is
post-v0 work (§5, M4). New checks are added **reactively** per the estate compound-learning
rule, never as a speculative tolerance/manufacturability DSL.

This dissolves most of the differentiation claim — fine, since positioning is estate-first
(§2). The value is a correct, honest internal instrument, not a moat.

### 3.1 The red-team, distilled

Read this before writing code. It is what keeps the gate honest.

Reviewed 2026-07-20 by adversarial first-principles distillation; the kill case was run by an
**independent agent** in a separate context that had not seen the distillation. Calibrated
for an internal tool — moat/TAM objections voided, only frame-independent cuts applied.
Verdict: **KILL-as-scoped**, reframe adopted. Full text:
`git show 2731ae3:docs/reviews/001-wedge-red-team.md`.

**Survived.** Deterministic checks are real and trustworthy for **global, static, foreseen**
properties: build-succeeds, manifold, envelope, gross mass/volume, foreseen clearances, FDM
overhang. Notably they catch **silent feature loss in boolean fusion** — a feature absorbed
during fusion that still reports manifold with volume inside a loose band. Genuinely
valuable and otherwise invisible. A pre-declared spec earns its cost in exactly two modes:
regression across many regenerations, and offloading arithmetic humans eyeball badly.

**Did not survive.**

- **Full-taxonomy defect coverage — FALSE.** Realistic catch rate is roughly one third, and
  only for defects named *in advance*. The dominant class in agent-generated CAD is *local,
  unforeseen, sequential, or fidelity* — gusset overlapping a hole, a through-hole that
  isn't through, datum-offset mating feature, assembly-sequence blockage. Bbox/volume/
  manifold are structurally blind to all of these. Catching them needs a per-feature
  assertion, which requires already knowing where the bug will be — circular.
- **Independence — FICTION as normally deployed.** One LLM authoring spec *and* geometry
  shares blind spots: correlated failure, not independent verification.
- **"Green gauge" is worse than "no gauge" when framed as sufficient.** It licenses skipping
  the ten-second render glance for exactly the defects it cannot see.

**Goodhart paths — the gaming routes §10 tests against.** (1) *One-sided clearance*:
"clearance ≥ min" with no upper bound lets a uniformly shrunk part pass while ruining a
press fit — hence two-sided windows, never min-only. (2) *Deletion beats repair*: negative
constraints are cheapest satisfied by removing the offending feature. (3) *Mass band rewards
hollowing or filling* to land in-band regardless of intent.

**ICP — where the surviving value is real.** Not "any agent-generated part": a part
**regenerated many times against a stable, small acceptance contract**. For a one-shot
generate-a-bracket, the render glance dominates.

**WINS IFF** the spec stays small and is reused across many regenerations; green is
documented as necessary-not-sufficient and never substitutes for viewing the render; new
checks are added reactively after a real recurring defect; clearances are two-sided; and
bands stay loose enough, with an owner, to survive OCCT/build123d/slicer drift.

**LOSES IFF** the spec is written once by the same intelligence that generates and framed as
a substitute for looking at the part; coverage is claimed as broad correctness; effort goes
into a general tolerance DSL for two hobby-scale consumers and the spec rots to a
bbox+volume stub; clearance goes back to min-only; or tight bands throw false failures
across kernel bumps nobody maintains, so the gate is quietly disabled while still implying
verification.

## 7. M2 — The honest gate (test-first)

### 7.1 Modules and their dependency graph

The file table below reads linearly, but the actual dependency graph has real parallelism.
Use this graph, not just the table order, when deciding what a solo builder does in sequence
versus what parallel subagents in separate worktrees can take concurrently (see the
Handoff's Execution model section):

```text
  Wave 0 (optional, single agent, ~5 min):
    verify/types.py  — PreflightResult, BrowserResult dataclasses/models.
    Defining these first lets waves 1-2 code against a fixed contract.

  Wave 1 (parallel — 2 worktrees, no shared dependencies):
    preflight.py            viewer/index.html
    (pure, no CAD/browser    (static three.js + STLLoader, no deps on preflight)
     deps — numpy+trimesh)

  Wave 2 (parallel — 2 worktrees, both depend only on viewer/index.html from wave 1):
    browser.py               render.py
    (load-check via the      (multi-view capture via the
     viewer)                  same viewer + polyfetch pattern)
    — do NOT start wave 2 until viewer/index.html exists; browser.py and render.py
      do not depend on each other.

  Wave 3 (single agent, needs preflight.py + render.py merged):
    report.py  — assembles PreflightResult + render output into one artifact

  Wave 4 (single agent, needs everything above merged):
    cli.py  — wiring only, no check logic. This is why it is built last regardless
              of how much of the above ran in parallel.
```

Merge each wave back to the integration branch before starting the next wave that depends on
it. Wave 1 and wave 2 are each internally parallel but sequential *relative to each other*
(wave 2 needs wave 1's `viewer/index.html`); waves 3 and 4 are strictly sequential
integration steps with no parallelism to extract.

`browser.py` and `render.py` are the only polyfetch-dependent pieces — see the separability
note in §9.

| File | Responsibility |
|---|---|
| `src/caxgauge/verify/preflight.py` | `preflight(mesh) -> PreflightResult`. Checks: **file integrity** (`struct`), **watertight/manifold** (`trimesh`), **bbox within envelope**, **volume/mass within band**; reports genus (Euler characteristic) without asserting on it. Structured per-check pass/fail, explicitly labelled necessary-not-sufficient. Pure — no agent, no network, no CAD/browser deps. **Never repairs** the mesh (repair hides the defect it should report) |
| `viewer/index.html` | Static three.js + STLLoader. Loads a mesh from `?mesh=`; named camera presets (front/iso/top/right). On load failure it must **throw** (fire `pageerror`) — do not rely on a readable success flag (isolated-world caveat, §9.2) |
| `src/caxgauge/verify/browser.py` | `browser_load_check(mesh) -> BrowserResult`. Serve the viewer locally (`localhost` or `127.0.0.1` — both unguarded since polyfetch #181, §9.1), load via env-borrowed polyfetch `render_session`, capture `console_errors` + `network_failures` + `pageerror`. A mesh that won't parse is a **hard fail**. Stub/SKIP when polyfetch/Chromium absent |
| `src/caxgauge/verify/render.py` | Multi-view PNG capture through `polyfetch` at the named camera presets. **The primary gate** — makes the human glance instant |
| `src/caxgauge/report.py` | Assemble render + preflight verdict into one human review artifact. Green shown as *necessary, not sufficient*; never the word "verified" |
| `src/caxgauge/cli.py` | `caxgauge check MESH [--envelope X,Y,Z] [--volume-band MIN,MAX] [--out DIR] [--no-render]`. Parse, call preflight + browser + render, write the report, exit non-zero on a hard fail. Thin — no check logic lives here |

**The CLI is the M3 contract.** M3's done-when is *"a consumer runs the gauge via a
documented command"*, so the command has to exist and be stable by the end of M2. Keep the
surface this small; new checks arrive as report content, not as flags.

**An unsupplied bound is `SKIP`, never `PASS`.** `--envelope` and `--volume-band` are
optional because most first runs will not have them, but a bbox check with no envelope must
report `SKIP` in the report and must not count toward green. Reporting "no bound given" as a
pass is the §3.1 false-confidence failure in miniature, reachable by default rather than by
gaming.

### 7.2 Deterministic checks — implementation notes

- **File integrity** (corrected 2026-10-06): the `struct` pattern in
  `../so101-biolab-automation/src/hardware/slicer/validate.py:141-183` (identical scope in
  `../i3mega-pipettebot/tools/slicer/validate.py:226-256`) checks only header size, triangle
  count > 0 and expected byte length. It is a **file-integrity** check and **cannot detect
  non-manifold geometry** — earlier text here called it a watertight/manifold check, which
  overclaimed. Keep it, labelled honestly.
- **Watertight/manifold**: `trimesh` — `is_watertight`, `is_winding_consistent`, `volume`,
  `euler_number`, all confirmed present on installed 5.1.1. **Do not use `body_count`**
  without adding `scipy`: it raises `ModuleNotFoundError` when scipy is absent (verified
  empirically). OCCT `is_valid()` is **removed** from this layer: it needs the B-rep solid,
  which the gauge never sees under the locked STL input contract (§2) — it belongs at the
  consumer's export step or M5. `prusa-slicer --info` is not used here either (unverified
  output format, binary absent in CI, duplicates trimesh).
- **Silent boolean-fusion feature loss** (the headline value): **trimesh does not catch it** —
  a part that lost a feature in fusion stays watertight. In M2 it is caught only by
  `--volume-band`. Face/edge counts on an STL are tessellation-dependent, so they are not
  asserted; genus (Euler characteristic) is reported but only asserted from M4's regression
  spec (it catches absorbed *through*-holes, not blind features). Full manifest-diff
  regression is M4, not here.
- **bbox / volume**: compute from the mesh; assert within envelope/band. Two-sided where
  applicable.

### 7.3 Fixtures and acceptance

Fixture-driven, no agent, no VLM. Fixtures under `tests/fixtures/` (kept out of the
`.gitignore` mesh exclusion deliberately).

1. **Good part** — passes all preflight checks; browser-load clean.
2. **Non-manifold mesh** — fails the watertight check; other checks may still run.
3. **Feature-absorbed mesh** (silent fusion loss) — fails the **volume-band** assertion. The
   test **must supply `--volume-band`**: with no band the check reports `SKIP` (§7.1) and the
   test asserts nothing. The fixture is a **committed STL exported once from build123d**, not
   generated in-test (trimesh has no boolean engine without an extra backend).
   ***This is the headline test.*** If it passes green, the preflight is worthless.
4. **Oversize part** — fails the bbox/envelope assertion.
5. **Un-parseable mesh** — `browser_load_check` returns a hard fail via `pageerror`; assert
   the failure is caught (force the failure to confirm listeners fire, §9.2).
6. **Honesty test** — a part that passes preflight but is visibly wrong must NOT yield a
   "verified" verdict.
7. **Unbounded-check test** — run the CLI with no `--envelope` and no `--volume-band`. The
   bbox and volume checks must report `SKIP`, the report must say which bounds were absent,
   and the run must not present as fully green.
8. **Stub-mode CI (primary gate)** — full path runs with no build123d, no Chromium; asserts
   the result shape and the necessary-not-sufficient labelling; `SKIP`s tool-dependent legs
   cleanly.

Property tests (Hypothesis): a generated box of size X passes its own bbox assertion and
fails a deliberately perturbed one.

## 9. Substrate — `polyfetch-scrape`

Rendering geometry headlessly is the awkward part of M2. Native VTK/OpenGL offscreen
rendering needs GL/X11 in CI and is fragile. Instead: render in a **minimal static three.js
page** and drive it with `../polyfetch-scrape` (Apache-2.0, Python ≥3.11, v0.7.0), which
owns Patchright/Chromium install, launch, teardown, capture and an SSRF guard.

What that buys: multi-view capture via `render_session(url)`; VP8 `.webm` turntable video
(`Response.video_path`); viewport / orientation / device emulation; a deterministic
browser-side gate via `page.on(...)`; and E2E UI testing of the report itself.
`render_session()` capture is **always on** — `s.console_errors` and `s.network_failures`
fill for the whole session. One-shot `fetch()` needs opt-in
(`RenderOptions(capture_console=True, capture_network_failures=True)`). `aria_snapshot()` is
the current API; `page.accessibility.snapshot()` was removed upstream. This makes
`browser.py` mostly wiring, not new logic.

**Consumption:** env-borrow via `uv run --directory ../polyfetch-scrape` (see its
`USING.md`) — no venv poisoning. **In a git worktree** (`.claude/worktrees/…`) the relative
`../polyfetch-scrape` does not resolve; use `/workspaces/qte77/polyfetch-scrape`. The gauge
finds the checkout via `CAXGAUGE_POLYFETCH_DIR` (`verify/substrate.py`); unset means the
browser legs `SKIP`. `serve_viewer(mesh)` serves `viewer/` and the mesh from one origin.

**Separability escape hatch — largely moot as of 2026-10-09.** The open question was whether
E2E UI testing of one's own app is in scope for polyfetch. Its `USING.md` now documents
`render_session` explicitly as a "scripting substrate" — the live Patchright page with full
DevTools capture, "for flows the CLI doesn't cover" — which answers it in practice.
[#144](https://github.com/qte77/polyfetch-scrape/issues/144) is still open, but its actual
scope is narrower: a reusable headless ui-check helper shared across consumers; it does not
block M2. If the substrate ever fails anyway, the fallback stands: `preflight.py` is pure and
browser-free, so ship preflight + a manually-opened viewer and treat `browser.py` /
`render.py` as the separable piece — the honesty constraint still binds (preflight-only is
not a shippable *gate*, §5). Upstream issues filed 2026-07-20, both **closed**:
[#180](https://github.com/qte77/polyfetch-scrape/issues/180) (isolated-world caveat, now in
`USING.md`, 2026-09-24) and [#181](https://github.com/qte77/polyfetch-scrape/issues/181)
(SSRF guard, 2026-09-30 — see §9.1).

### 9.1 ~~Use `localhost`, not `127.0.0.1`~~ — obsolete since polyfetch #181 (2026-09-30)

**Corrected 2026-10-09, re-read at source.** This section used to warn that polyfetch's
`check_ssrf` rejected literal IPs, so `127.0.0.1` would raise where `localhost` passed. That
was true when written. polyfetch commit `a69e6a5` (2026-09-30, closing #181) replaced it with
an **escalation-only** guard (`utils/_ssrf.py` module docstring): the **seed** URL a caller
passes in is never blocked — "including a literal internal IP or a name resolving to one
(`localhost`, a LAN alias)" — and only URLs *derived* from an external seed, on the discovery
paths, are checked. polyfetch's `USING.md` also states that plain `fetch()` "is **not**
guarded at all", which settles this section's old unverified inference about `client.py`.

**Consequence for M2:** the viewer may be served on `localhost` or `127.0.0.1`; neither is
guard-checked. No trap left here.

### 9.2 Non-negotiable constraints

From `../polyfetch-scrape/AGENT_LEARNINGS.md`. Adopt from day one rather than rediscovering.

1. **Never assert three.js state via `page.evaluate`.** Patchright is a stealth Playwright
   fork running `evaluate` in an **isolated world**; page-script globals (`window.THREE`,
   module-scoped vars) read back `undefined` even when the scene rendered correctly. Their
   log records exactly this false negative. **Screenshots are ground truth for "did it
   render"; `page.on(...)` for "did it load".** Reserve `evaluate` for DOM you set or read
   structurally. This is the single highest-cost trap in the integration.
2. **Capture all four events.** Uncaught/parse errors fire `pageerror`, *not* `console`.
   Blocked or non-2xx resources fire `requestfailed` / non-200 `response`. Listening to
   `console` alone silently misses most real failures.
3. **A clean console means "no error on this network", not "no error".** Force a failure
   once and confirm the listeners fire. **Done in wave 1:** on Patchright, page-script errors
   were not captured, so gate on the viewer's `body[data-state]` + screenshots, not
   `pageerror` (`viewer/README.md` → "Success / failure signals"; upstream
   [polyfetch#253](https://github.com/qte77/polyfetch-scrape/issues/253)).

## 10. Verification strategy

- **Fixture property tests** — §7.3.
- **Goodhart tests (from §3.1).** Assert the known gaming paths are *not* scored green: a
  part shrunk uniformly must fail a two-sided clearance window; a part with the offending
  feature deleted must not score better than the broken original — the report must surface
  the deletion, not hide it.
- **Necessary-not-sufficient honesty test.** Feed a part the preflight passes but that is
  visibly wrong (datum-offset hole). Assert the system **does not** report success — it
  presents the render for human decision and never emits a "verified/correct" verdict.
  Guards the false-confidence failure §3.1 calls worse-than-no-gauge.
- **Stub-mode CI (primary gate).** Runs end-to-end with no build123d, no OpenSCAD, no
  Chromium, no VLM; asserts the report is produced and green is labelled
  necessary-not-sufficient.
- **Golden-path integration (marker-gated).** One real part, real render capture.
- **Real acceptance test (M3).** The gauge runs over an existing part from
  `so101/src/hardware/parts.json` or `i3mega/tools/cad/parts.json` and produces a clean
  preflight + render a human accepts.
- **Regression test (M4).** Same part across a simulated kernel/tolerance shift: assert
  `verify/regression.py` surfaces the drift rather than silently passing or throwing a false
  failure.

|---|---|---|---|
| Schema validity | Gate | `ifcopenshell.validate` | none needed |
| IDS conformance | Gate | IfcTester (§13.4) | `--ids FILE` from the user or authority; absent → `SKIP` |
| Clash / clearance | Gate | IfcClash (intersection, collision, clearance) | `--clash-config FILE` (clash sets + tolerance); absent → `SKIP` |
| Per-element mesh validity | Gate | `ifcopenshell.geom` → the same trimesh checks as CAD | none needed |
| Quantity consistency (declared `Qto_` vs computed) | Gate | `ifcopenshell.util.shape` | `--qto-band PCT`; absent → `SKIP` |
| Building-code interpretation | **Inform only** | LLM/retrieval note | never gates |

New flags follow §7.1's rule: each one supplies a **declared bound**, never a new check
mode, and an absent bound is `SKIP`, never `PASS`. **The gauge never writes IDS rules or
clash sets itself** — authoring the spec and checking against it in one tool is the
correlated-failure problem §3.1 killed.

### 13.3 Render and report

- Render path: IFC → `.glb` (IfcOpenShell's glTF serializer or the `IfcConvert` CLI — confirm
  which ships in the pip package at build time) → the existing three.js viewer via
  `GLTFLoader`. One loader added to §9's substrate; `web-ifc-three` is deprecated and its
  successor needs three ≥ 0.182, so it stays out.
- The report must separate **"missing in the model"** from **"not mapped on export"** —
  property mapping is a user setting in Revit's exporter, so a correct model can fail IDS for
  configuration reasons.
- **Never repair.** No IfcPatch, no `fill_holes` in a check path — a repaired model hides the
  defect the report exists to show.

### 13.4 Dependencies (recommended default; owner confirms, risk 9)

`ifcopenshell` + `ifcclash` in an optional `bim` extra. IfcTester is called as an
**external CLI** (stub-mode `SKIP` when absent, like every other external tool), so its GPLv3
`bcf-client` dependency stays out of this package's dependency tree.

### 13.5 Data handling

Real project data may be contractually restricted. Any inform-only LLM note must support a
**local/self-hosted endpoint**, and sending model data to an external API is **opt-in**,
never the default.

### 13.6 What is still unverified

Behaviour on **real exported project data** — every empirical check so far used a synthetic
IFC model. APS pricing. Whether the glTF serializer ships in the pip package.
